# 常量

4核心优化：数据清洗“三剑客”

网页上看到的是给人看的文本（(2026)、1h 39m、2026/07/24 (US)），但存进表格时我们希望它是规范、可计算的数据。三个小函数分别解决年份、日期、时长。

源代码 14-31 行# ① 年份：去掉括号
def get_movie_year(movie_years):
    movie_year = movie_years[0].strip() if movie_years else ''
    return movie_year.replace("(", "").replace(")", "")   # "(2026)" → "2026"

# ② 上映日期：正则抽取纯日期
def get_movie_publsh_date(movie_dates):
    movie_date = movie_dates[0].strip() if movie_dates else ''
    return re.search(r"\d{4}-\d{2}-\d{2}", movie_date).group()   # "...2026-07-24..." → "2026-07-24"

# ③ 时长：统一换算为分钟
def get_movie_cost_time(movie_cost_times):
    movie_cost_times = movie_cost_times[0].strip() if movie_cost_times else ''  # "2h 20m" / "40m" / "2h"
    h_res = re.search(r"(\d+)h", movie_cost_times)
    m_res = re.search(r"(\d+)m", movie_cost_times)
    h = int(h_res.group(1)) if h_res else 0
    m = int(m_res.group(1)) if m_res else 0
    return h * 60 + m      # "2h 20m" → 2*60+20 = 140

逐个拆解

① get_movie_year —— 清洗不是一定要用正则

年份原文是 (2026)，只是多了一对括号。杀鸡不必用牛刀，直接用字符串方法 replace 替换掉左右括号即可，还能链式调用两次。

② get_movie_publsh_date —— “匹配并抽取”

正则 \d{4}-\d{2}-\d{2} 的含义：4 位数字-2 位数字-2 位数字，即 YYYY-MM-DD。re.search 在长字符串里“找”第一个匹配，.group() 取出这段文本——把“带地区后缀的原始日期串”洗成了标准 ISO 日期。

⚠ 这里有一个潜伏的 Bug：当 movie_dates 为空或字符串里没有 YYYY-MM-DD 格式时，re.search(...) 返回 None，再调用 .group() 会直接抛 AttributeError 中断整个程序——注意 05 版这里是有兜底（空则给 ''）的，07 版反而“退步”了。正确的写法是先用 result = re.search(...)，再判断 if result。

③ get_movie_cost_time —— 最有价值的规范化

网页时长有 2h 20m、40m、2h 三种形态，没法比较大小。解决办法：

  • 用两个带分组括号的正则分别抠出小时数和分钟数：r"(\d+)h"、r"(\d+)m"。
  • int(h_res.group(1)) if h_res else 0 —— 匹配不到就按 0 处理。这个“匹配失败给默认值”的写法，优雅地兼容了三种形态，是整个函数健壮性的关键。
  • 统一换算成分钟整数后，CSV 里的时长就能直接排序、算平均、画图表了。

moive_info = {
    "电影名": movie_names[0].strip() if movie_names else '',
    "年份":   get_movie_year(movie_years),          # ← 交给清洗函数
    "上映日期": get_movie_publsh_date(movie_dates),  # ← 交给清洗函数
    "标签":   ",".join(movie_tags) if movie_tags else '',
    "时长":   get_movie_cost_time(movie_cost_times), # ← 交给清洗函数
    "评分":   movie_scores[0].strip() if movie_scores else '',
    # ……语言 / 导演 / 作者 / 宣传语 / 简介 同 05 版
}
return moive_info
  • XPath 是“看浏览器复制的绝对路径”（//*[@id='original_header']/div[2]/…），命中率高但非常脆弱——网站改一次版就要重新复制。教学场景没问题，工程上建议改用更稳定的 class / 语义锚点。
  • 防御式取值：x[0].strip() if x else '' —— XPath 抽不到时返回空列表，直接 x[0] 会 IndexError；给默认空字符串保证“缺字段不崩、整行不丢”。
  • 多值字段 join：一部电影可以有多个类型标签，XPath 抽回的是列表，必须 ",".join(...) 拼成字符串才能写进 CSV 的一个单元格。
  • 清洗收口在字典处：凡是需要清洗的字段（年份/日期/时长），在这里统一“转交”给专门的清洗函数，职责单一、便于复用与测试。

6save_all_movies：一次落盘

源代码 82-86 行def save_all_movies(all_movies):
    with open(MOVIE_LIST_FILE, mode='w', newline='', encoding='utf-8') as csvfile:
        writer_csv = csv.DictWriter(csvfile,
            fieldnames=["电影名","年份","上映日期","标签","时长","评分","语言","导演","作者","宣传语","简介"])
        writer_csv.writeheader()   # 写表头
        writer_csv.writerows(all_movies)   # 一次写入全部字典行
  • csv.DictWriter 与“字典列表”天然匹配：fieldnames 既是表头，又规定了每行取哪些键、按什么顺序写。
  • 中文不乱码的两件套：encoding='utf-8' 防乱码；newline='' 防止 Windows 下每两行之间多一个空行。
  • mode='w' 是“覆盖写”，每次运行都会重生成整份文件（简单但会丢掉历史数据）。

7main：翻页 + 遍历 + 汇总

源代码 92-135 行（节选）def main():
    all_movies = []   # 汇总容器
    for page_num in range(1, 6):          # 抓前 5 页
        # ① 第1页用 GET，第2页起用 POST（模拟浏览器提交筛选表单）
        if page_num == 1:
            response = requests.get(TMDB_TOP_URL_1, timeout=60)
        else:
            response = requests.post(TMDB_TOP_URL_2,
                f"air_date.gte=&air_date.lte=&...&page={page_num}&...&sort_by=vote_average.desc&...",
                timeout=60)
        print("状态码：", response.status_code)   # 是否 200
        print("页面长度：", len(response.text))   # 正常应几十 KB 以上

        # ② XPath 定位每部电影的卡片节点
        document = html.fromstring(response.text)
        movie_list = document.xpath("//*[@class='flex w-full']")
        print("找到的电影数：", len(movie_list))

        # ③ 逐个进入详情页
        for movie in movie_list:
            movie_urls = movie.xpath("./@href")       # 取相对路径
            if movie_urls:                            # 过滤无链接的广告等元素
                movie_info_url = TMDB_BASE_URL + movie_urls[0]   # 拼接完整 URL
                movie_info = get_movie_info(movie_info_url)      # 抓详情 + 清洗
                all_movies.append(movie_info)

    # ④ 全部完成后统一保存
    save_all_movies(all_movies)

三个值得品的设计点

① 翻页 POST 的 f-string 拼参数

第 78/103 行那一大段表单字符串里，唯一变化的是 page，因此用 f-string 只把页码插进去（page={page_num}），其余筛选条件（按评分降序 sort_by=vote_average.desc、投票数≥300 vote_count.gte=300）原样保留。

② “状态码 + 页面长度”自检日志

注释写着“页面长度正常应该在几十KB以上”——这是爬虫的经典自检手段：200 不等于成功，如果被反爬重定向到验证码页，页面会明显变短。打印出来一眼可辨。

③ if movie_urls 过滤 + 统一 URL 拼接

榜单页的节点不全是电影（可能混入推荐位），用 if movie_urls: 把没有链接的节点筛掉；详情页返回的是相对路径，所以用常量区的域名补全。

8隐藏的坑（学爬虫必踩）

1. re.search 返回 None（已在 4.② 标注）

日期正则匹配不到时空指针崩溃，优化版最大的隐患。修复：先保存结果再判空。

2. csv_data/ 目录必须存在

open() 不会自动创建父目录，目录不存在直接 FileNotFoundError。可用 os.makedirs(..., exist_ok=True) 兜底。

3. 没有请求头与延时

没设置 User-Agent，5 页 × 20 部电影连续快速请求，极易触发限流/封 IP。建议加 headers、每请求间 time.sleep()。

4. 无异常处理，一崩全丢

任何一部电影请求超时都会中断主流程，已抓数据全部丢失。可用 try/except + 失败跳过，最后统一保存。

9如果继续做下去，还能怎么改

  • 改用官方 / 免费 API：TMDB 提供公开 API（无需解析 HTML），请求更稳定、字段更干净。这也说明：抓网页是“没有 API 时的退路”，优先找接口。
  • 引入“解析层重试”：单个字段失败不放弃整条记录，二次 XPath 或备用路径兜底（对应第 5 章里注释掉的备用路径写法）。
  • 清洗逻辑单元化可测试：把“三剑客”挪到独立模块 + 写断言测试（2h 20m → 140 这种纯函数最适合）。
  • 存储升级：追加写入 mode='a' 保留历史快照；或换成 pandas → Excel / SQLite，便于后续分析“高分电影都出自哪年、哪种类型”。
  • 并发提速：详情页彼此独立，可用线程池并发抓取，速度提升数倍（注意礼貌限速）。
